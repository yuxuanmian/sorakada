# 010：正则搜索与编辑区高亮、定位修正

**日期**：2026-10-12

**状态**：已完成。2026-10-12 用户确认实机测试通过，反馈问题已修正并验收。

**范围依据**：用户要求将本轮讨论落到文档；采用讨论末尾的交互默认规则。

## 目标

在现有当前文档搜索/替换上增加正则模式，并解决三个可见问题：当前行与文本选区背景过于相近、搜索命中显示不够完整且当前命中不明显、触发搜索后未自动选中最近候选项。

本规格是 010 的权威需求入口。这里的“颜色统一”限定为编辑区字符背景与搜索命中状态，不扩展为应用整体换色。

## 决策与行为

### 1. 当前行、选区与搜索高亮

| 状态 | 显示规则 |
| --- | --- |
| 当前行 | 保持较弱的灰色整行背景及现有行号反馈。 |
| 普通文本选区 | 使用明显的蓝色字符背景，视觉强于当前行；单行、跨行和三连击整行选择使用一致底色，不受当前行背景覆盖；编辑器失焦时仍可辨认。 |
| 普通搜索命中 | 所有命中范围使用一致、明显偏黄且对比度更高的金黄色字符背景，完整覆盖命中字符；文字使用清晰的深色前景。 |
| 当前搜索命中 | 在相同金黄色背景上额外添加 1px 白色描边；白色只用于边框，不改成白底。 |
| 零宽搜索命中 | 没有字符可填色，用细竖线标记位置；当前位置额外使用白色描边提示。 |

- 搜索 `sty` 时，每一处命中的三个字符 `sty` 都完整高亮；不把整词 `style` 或整行当作命中范围。
- “所有命中”指当前文档中的全部匹配；滚动到任何位置时该处命中均正确显示，不要求一次性渲染视口外的全文。
- 搜索命中与蓝色选区重叠时，命中范围的金色背景和当前命中的白色描边保持可见；选区的其余部分仍显示蓝色。
- 每次只有一个当前命中。不能因为多选区中有多个范围与匹配重合，就把它们全部画成当前命中。
- 跨行命中按每行片段显示背景与描边。描边不得改变字符位置、行高、换行或滚动布局，不得被当前行/选区遮住。
- 普通文字、被选文字和高亮文字均需清晰可读。具体蓝色、金色色值由实现时结合现有深色背景选定，本规格不冻结未经视觉验证的色值。

### 2. 自动选择最近命中

- 打开搜索/替换且存在有效非空查询时，立即选择最近命中并滚动到可见位置；有合规选区时，先沿用既有预填规则，再进行定位。
- “最近”指从触发时的编辑器光标位置（主选区 `head`）向后找到的第一个命中，包含恰好从该位置开始的匹配；后面没有结果时环绕到文档开头。
- 输入或修改搜索词、切换大小写、切换正则开关时，自动更新当前命中和高亮。连续输入不得仅因前一次自动选区改变光标位置，就无故跳过仍符合新查询的当前命中。
- 自动定位只改变编辑器选区与阅读位置，不抢走搜索栏输入焦点、不打断连续输入或中文输入法组合过程，不修改正文及撤销历史。
- 上一个/下一个按用户指定方向导航并环绕；零宽匹配必须继续前进，不反复停在同一点。只有一个命中时允许环绕后仍停在该命中。
- 计数展示当前命中在文档顺序中的真实序号与总数。例如文档共有两处匹配，当前为第一处时显示 `1 / 2`，定位第二处时显示 `2 / 2`。
- 空查询不选择候选项、不保留高亮；有效查询无结果时显示 `0 个结果`，禁用导航与替换，不无故移动原有选区。
- 无命中时，导航和替换按钮置灰且不可点击；鼠标悬停保持普通箭头，不显示禁止图标。
- 仅切换查找/替换的展示模式时，保持已有查询、选项与有效当前命中，不把当前搜索命中再次预填成新的表达式。
- 搜索栏已打开时，在编辑器手动选中其他文本后再次按 Ctrl+F，应以新选区替换查询（正则模式仍进行转义），并聚焦、选中搜索输入框；没有新选区时保留查询。不得把自动定位产生的当前命中误判为新的手动选区。

### 3. 正则表达式查找与替换

- 在现有搜索输入框的 `Cc` 旁增加 `.*` 开关，默认关闭；提供清晰的名称、开关状态和键盘可达性，不另建搜索界面。
- 关闭时保持 009 的普通文本搜索语义；开启时按浏览器常见的正则表达式语法匹配，支持字符类、量词、分组、锚点与跨行匹配。
- 输入原始表达式，例如 `item\d+`，不使用 `/表达式/flags` 包装；大小写由 `Cc` 控制，`^`、`$` 对每一行生效。
- 查找导航、数量、当前序号、高亮和替换必须使用同一套匹配规则；普通模式与正则模式均遵循前述自动定位行为。
- 开关切换保留搜索框原文、替换文本与大小写选项。同一文档切换查找/替换时保留正则开关，不新增持久化设置。
- 正则模式下，从编辑器选区预填的新查询应转义特殊字符，使预填默认查找选区的实际文本；已有查询不会在模式切换时被重复转义。单行、长度不超过 200 字符等既有预填限制继续生效。
- 无效表达式在搜索栏就地显示“无效的正则表达式”，清除旧计数、当前命中与高亮；按钮和快捷键均不能导航或替换。修正表达式后自动恢复，无需关闭重开，也不得弹出另一套搜索面板。
- 支持零宽匹配，例如 `^`、`$`。计数和导航包含这些位置；替换可在位置插入内容，例如给每行添加前缀或后缀。一次全部替换中的每个原始匹配只处理一次。
- 正则替换支持数字捕获组 `$1`–`$99`、完整匹配 `$&` 和字面美元符号 `$$`；未参与匹配的可选捕获组替换为空字符串。保留既有替换文本转义行为和空替换能力；普通模式不解释捕获组引用。
- 单次替换仅处理当前命中，然后定位下一个；没有有效当前命中时先定位，不误替换其他文本。全部替换必须一次撤销完整恢复，不能与相邻的普通输入合并为同一次撤销。

## 范围与约束

包含正则开关、错误反馈、捕获组及零宽替换、编辑区字符背景、当前命中白色描边和自动定位修正。

不包含工作区/跨文件搜索、独立全词开关、选区内查找开关、搜索历史、命名捕获组替换、语法高亮、设置页、主题切换或全局主色/背景/菜单/文件树重设计。表达式本身可使用词边界语法。

- 继承 [009 搜索替换规格](../009-search-replace/plan.md) 的搜索栏布局、快捷键、焦点返回、输入框撤销隔离、标签切换关闭与清理规则。关闭搜索或切换文档后，延迟任务不得重新显示旧命中。
- 保留 100ms 计数防抖和 1000 项计数上限；计数上限不限制导航或替换全部的范围，也不限制后续滚入视口的命中高亮。不得因等待计数而延后当前命中选择或可见高亮。复杂正则的执行成本取决于表达式，本阶段不要求新增后台搜索或强制超时系统。
- 遵守 [AGENTS.md](../../AGENTS.md) 与[项目原则](../../.specify/memory/constitution.md)。正文、选区和撤销历史仍由 CodeMirror 持有，颜色由现有集中语义 Token 管理，不在组件中硬编码配色。
- 维持现有保存、脏状态、文件格式、文档切换和文件监视语义；本功能不新增磁盘写入路径。

| A02 | 文档含 `<style>` 与 `</style>`，搜索 `sty`：两处 `sty` 均完整金底，当前一处额外白色描边；导航后描边转移，其他命中底色不变。 |

| A04 | 连续输入、删除关键词或切换 `Cc`/`.*`：自动更新最近匹配，焦点留在输入框，不跳过仍有效的当前匹配；中文组合输入不被打断。 |
| A05 | 在 `item1 item22 ITEM3` 中开启正则搜索 `item\d+`：忽略大小写时三处，区分大小写时两处；导航、计数与高亮范围一致。关闭正则后按普通文本匹配。 |
| A06 | 正则模式输入 `[`：显示错误，旧结果清空，按钮与 Enter/替换快捷键均不修改正文；修正后立即恢复。清空查询和有效但无结果的查询按各自规则展示。 |
| A07 | 在两行非空文本中搜索 `^` 或 `$`：两处位置都有标记，双向导航可前进并环绕；全部替换为前后缀时每行只插入一次，一次撤销恢复全文。 |
| A08 | 用 `(item)(\d+)` 替换为 `$2-$1`：单次与全部替换正确重排；验证 `$&`、`$$`、未匹配可选组与空替换，普通模式中的 `$1` 作为普通文本。 |
| A09 | 替换前后各输入普通文本：撤销一次只撤销全部替换，不带走之前输入；编辑器失焦时，命中金底及当前白边仍可见。 |
| A10 | 有跨行命中、命中与选区重叠或多个选区时：所有命中完整可辨，只有一个当前白边；行高、字符位置与换行不变。滚动后新出现的命中也正确高亮。 |
| A11 | 超过 1000 处匹配时计数封顶提示，仍能导航、滚动高亮和替换全文；关闭搜索、切换标签或关闭最后一个文档后，无残留高亮或延迟旧计数。 |
| A12 | 在正则模式下选中含 `.`、`[` 的普通文本并唤起搜索：预填后匹配实际选区；随后切换查找/替换保留表达式及选项。 |
| A13 | 搜索栏已开时，在编辑器手动选中另一个词，再按 Ctrl+F：查询替换为新选区且焦点回到搜索输入框。直接重复 Ctrl+F 时原查询（尤其是正则表达式）不被自动命中覆盖。 |

## 与既有规格的关系

- 009 继续作为已完成的基础阶段。本规格扩展其“不支持正则”的阶段范围，并替代其“普通命中暗金、当前命中亮金”的区别方式，改为统一金底、当前白边；自动定位是对 009 既有意图的明确与修正。
- 008 的“选区强于当前行”原则继续有效。本规格允许调整编辑器选区及搜索语义 Token，并要求同步相关基线断言；不授权重做其他区域配色。
- 先前对 010 的“统一全局交互主色”设想已被本轮澄清替代。此前回滚的 010 文档不作为执行依据。
