## 目标

将 001～010 已具备核心能力的 Sorakada 整理为交互统一、中文可用、可安装交付的 Windows Alpha 应用。011 只完善应用级基础设施，不增加编辑器功能，不重构已稳定的文档或文件系统核心。

本文件是 011 的权威需求入口，替代本次聊天中粘贴的设计草稿。正文和验收定义行为；文末 Checklist 仅用于实施核对，不另起一套需求或详细任务计划。实现者应结合最新代码选择实现方式，不以建议组件名或路径代替代码检查。

## 决策与行为

### 1. Dialog System

- 基于既有 `src/ui/overlay/OverlayRoot.tsx`、主题语义 Token 和 `@base-ui/react`，封装统一 Dialog 展示层及调用宿主，例如 `SoraDialog`、`DialogHost`。展示层不得持有文档保存、关闭等业务事实。
- 优先保留 `FileDialogService` / `WorkspaceDialogService` 的确认、选择接口及结果语义，确认底层改为 Promise 式 React Dialog；原生 open、save、文件夹选择器继续使用。错误反馈接口允许按第 3 节做最小扩展。
- 迁移未保存文档（保存/不保存/取消）、磁盘外部修改覆盖、重新加载丢弃修改、移入回收站确认，以及确实需要阻塞阅读的严重错误。普通可恢复的文件操作失败不因级别为 error 就变成阻塞 Dialog。
- 用户决策返回稳定枚举/布尔值，不依据翻译后的按钮文字判断结果。取消、Esc、关闭弹窗、宿主卸载及异常路径均以不执行破坏性操作为默认结果；卸载须结束当前及排队请求，不残留挂起 Promise。
- 同一时间只显示一个需要决策的 Dialog，不同请求串行排队。原生 Close、标题栏关闭及 `app.exit` 等退出入口共享或阻止并发关闭流程，不能产生两套未保存确认链。
- 决策 Dialog 显示期间暂停背景编辑和打开、保存、关闭、查找等应用业务命令。全局快捷键、菜单等入口均遵守该规则，不能仅依靠焦点陷阱。Dialog 自身键盘操作、文本选择及复制仍可使用，重复退出请求合并到当前退出流程。
- 正确处理焦点陷阱、Esc 优先级及关闭后的焦点恢复；恢复至仍有效的原交互位置，不意外改变 CodeMirror 内容。遮罩点击按安全取消处理，不执行危险确认；危险动作不得获得意外的默认确认。
- 排队确认在展示前、用户决定在执行前，均须核对目标及相关状态是否仍有效。文件关闭、改名、外部变化或脏状态变化后，不执行已失效的删除、覆盖或丢弃决定；按既有安全规则取消或重新确认，不冻结或重写 Watcher。
- 选择“保存”后，真实写入成功且既有关闭守卫允许继续，才能关闭。写入失败、用户取消或源文档相关状态变化时保持文档与未保存内容；Dialog resolve 不等同于业务操作成功。

### 2. i18n 与现有文案迁移

- 引入 `i18next` / `react-i18next`，使用可静态校验的语义翻译 Key 和资源类型。资源可放在 `src/i18n/locales/{zh-CN,en-US}`，不要求复杂 Namespace 体系。
- 固定 `lng: "zh-CN"`、`fallbackLng: "en-US"`。不实现语言切换入口、系统语言识别、LocaleStore 或语言偏好持久化；库本身保留未来 `changeLanguage` 能力即可。
- 迁移全部现有应用控制的用户可见文案：菜单、Tab、Explorer、搜索栏、空状态、状态栏、确认弹窗、Toast、常见错误摘要、Tooltip、title、aria-label、输入占位等。中英文资源完整对应，英文不得只是占位符。
- 应用生成的 `UntitledN` 显示为本地化的“未命名N”，覆盖 Tab、窗口标题及确认文案等入口；保留内部文档身份和编号规则。真实文件名即使恰好是 `Untitled1` 也不得翻译，不通过字符串猜测真实文件与未命名文档。
- `CommandId`、文件错误码、保存/关闭结果及状态枚举仍是稳定机器值，UI 层负责翻译。不得翻译用户文件名、路径、正文或原始诊断文本。
- 业务组件不硬编码可见中文/英文。非 React 的静态菜单模型等通过注入翻译函数或等价方式生成文案，避免模块加载时冻结译文。业务层已有用户提示改用稳定语义及必要参数交给展示层处理，不把翻译后的文案当作业务事实。
- 保留 Windows 原生选择器的系统按钮与外观；应用控制的标题、筛选器名称纳入资源。NSIS 安装器语言独立配置，不依赖 React i18n。
- 不因 i18n 不必要地修改 `uiPreferences` schema，不重置或破坏已有布局偏好。

### 3. Notification System 与错误反馈

- 统一通知管理及展示，例如 `NotificationManager` / `NotificationHost` 与 `SoraToast`。位置为窗口右下角、Footer/状态栏上方，不改变编辑器布局，不自动抢焦点，不截获编辑器快捷键。
- 至少支持 info、success、warning、error。普通通知短时自动消失；保存失败等关键错误不自动消失，可手动关闭。悬停或展开详情时暂停计时。主动取消和普通 Ctrl+S 保存成功默认不提示。
- Error Toast 显示本地化摘要，可展开错误码、路径与原始诊断，并可复制保留的诊断内容。详情限高、可滚动；长路径、窄窗口不溢出。发生容量裁剪时，展示与复制均不得把不完整诊断冒充完整内容。
- 允许最小扩展前端错误反馈接口，使其携带操作、文档身份或路径、错误码、原始诊断等必要上下文；不从翻译后文字或原始错误字符串反推去重身份。保持 Rust IPC、文件错误机器值及保存/关闭结果语义不变，不为通知重构文件系统核心。
- 同一文件、同一操作、同类错误重复出现时，更新同一通知的次数与最近时间。连续 Ctrl+S 仍按既有业务并发规则正常尝试保存，不因去重或冷却跳过保存。
- 同一批次多个文件失败可汇总，并在容量范围内保留逐项详情。没有明确批次时，仅做谨慎的短时同类聚合，不把不同错误原因误当作相同错误。不同文件数与同文件重复次数分开统计；不要求为此永久保存所有文件身份。
- 默认最多显示 3 条 Toast。通知条目、详情占用、队列、聚合及冷却记录均须有上限；超限可合并错误、舍弃较旧逐项诊断，但须保留错误汇总，明确显示省略数量或诊断截断状态。最近的关键保存失败应优先可见，不能长期被三条旧持久错误挡在队列后。具体容量、超时、冷却及统计窗口由实现者确定并可验证。
- 用户关闭错误仅表示收起提示，不代表操作成功或故障解决。短时间同类重复错误不重新刷屏；不同错误原因仍可提示。对应保存重试成功后解除对应错误提示，不能错误清除其他文件或更新失败的提示。
- 普通 Toast 登记完成即可返回，不等待用户关闭。逐一复查现有 `showError()` 的 await 语义，保持调用方清理、异常及返回结果正确；文件关闭/退出仍依据实际保存结果中止，不能以通知登记、展示或关闭代替业务决定。确实需要阻塞阅读的严重错误保留明确的 Dialog 路径。
- 搜索栏无效正则、Explorer 错误行等现有就地反馈继续保留并翻译，不统一迁移为 Toast，不额外复制成持续刷屏的通知。
- 通知是本阶段手动保存流程的有限反馈机制，不实现通知历史、诊断持久化、诊断导出或复杂通知中心。后续可能采用 JetBrains 式积极自动保存，其触发、失败及冲突策略另行设计，不纳入 011。

### 4. Windows Alpha 安装包与 GitHub 构建

- 基于现有 Tauri 2 配置明确 Windows x64 NSIS 目标，输出可运行的 `setup.exe`。保持应用标识 `com.sorakada.editor` 稳定，确保图标、版本信息、安装/卸载入口及正常启动。
- NSIS 固定 `installMode: "currentUser"`，仅当前用户安装；安装器固定简体中文，不提供语言选择器。React i18n 与安装器语言分别配置。
- 验证全新安装、启动、已有版本覆盖安装、卸载。覆盖安装保留已有 UI 布局偏好；偏好损坏时按既有规则安全回退；卸载不得删除用户自行编辑的文件。
- 可采用预发布号，例如 `0.1.0-alpha.1`，最终版本由实际发布与覆盖安装基线确定；`package.json`、Cargo、Tauri 实际版本一致，不要求自动变更版本号。
- 覆盖安装验收须记录旧安装包来源、旧版本、新版本和安装模式，实际安装旧包并设置偏好后再覆盖安装新包。开发启动或同一构建启动两次不能代替升级验证；尚无旧包时须准备可复现的旧包基线并如实记录。
- 建立最小 `workflow_dispatch` GitHub Actions：Windows Runner 安装依赖 → Tauri/NSIS 构建 → `upload-artifact` 提供安装包下载。实际手动触发并下载验证，不要求自动 Release、签名、自动更新、多平台矩阵、PR CI 或分支保护。
- WebView2 按 Tauri 常规安装依赖处理。记录依赖行为与 Alpha 未签名限制；离线安装包、`.md`/`.txt` 文件关联、默认打开方式、系统托盘和商店发布不属于 011。
- GitHub 构建通过不等于安装验收通过。Windows 安装、升级、卸载须单独人工验证并记录；未执行项不得标为通过。
