**日期**：2026-10-17

**状态**：人工校验基本通过（2026-10-17 用户反馈）；已完成代码收尾与最终四项门禁，未将未逐项确认的专项检查标为全部通过。

**范围依据**：013 参考文档及本轮逐项确认的补充决策。

**核对基线**：当前 `feature-core` 代码与 012 已验收行为。

## 目标与范围

在既有 CodeMirror 6 编辑核心上增加完整单词起步的智能扩缩选、轻量括号／引号结构识别、继承已有光标的逐视觉行列拖选，以及 3px 无缝选区圆角。适配代码片段、普通文章、配置、日志和路径，保持通用文本编辑器的轻量定位。

复用 012 的多光标编辑、分段剪贴板、整行复制／剪切、撤销重做、Esc 层级及光标／视口动效；这些能力属于回归范围，不重新建设。

- 起始空行遗漏已确认由普通左键拖选触发。普通反向拖选需真实包含起始空行已有的换行；末尾无换行的空行不制造正文或越界偏移，以终端锚点及视觉提示表达。

## 行为要求

### 1. 单词边界与双击

双击只选择命中位置的最小合理单位，不沿扩选历史继续扩大。光标处于单词内时，`Ctrl+W` 首层与双击完全一致，共用边界及字符分类规则，不为鼠标和键盘维护两套词语义。

| 文本／命中位置 | 首层结果 |
| --- | --- |
| `dialogs.AbcCdd` 中的任一词 | 对应的 `dialogs` 或 `AbcCdd`，点号分隔。 |
| `dialogs-AbcCdd` 中的任一词 | 对应的 `dialogs` 或 `AbcCdd`，连字符分隔。 |
| `dialogsAbcCdd`、`camelCase`、`PascalCase` | 对应完整标识符，不按大小写变化拆分。 |
| `snake_case` | 整体选择，内部下划线保留。 |
| `hello, world` 中的 `world` | 仅 `world`，不含前面的空格或逗号。 |
| 连续空格／Tab 内 | 可选择所在的连续行内空白，不直接吞并邻词或换行。 |
| 中英文标点处 | 选择对应标点的最小合理单位，不捎带无关字符。 |

空格、Tab、换行、点号及其他分隔标点用于区分单词；英文字母、数字、内部下划线不因驼峰或数字交界被强行拆成小词。中文及中英文混排采用稳定的 Unicode／字符类别边界，不要求中文自然语言分词。路径、点号连接和小数可在后续层级扩大为有意义的片段，首层分隔规则必须一致。

光标恰好落在边界、连续标点、空行或换行处时，由实现选定少量确定的优先规则，并以实例固定；不产生无关跨行跳选，不切断 Emoji、代理对或组合字符。除下文明确补充的空行起步边界外，普通鼠标拖选及三击整行沿用现有可用行为。

### 2. 逐级扩选与快照缩选

- `Ctrl+W` 从空光标、已有局部选区或反向选区开始，寻找包含当前范围的更大合理范围。每个有效步骤必须扩大；重复候选跳过，到顶后不变，不振荡，不累积无效缩选步骤。
- 层级包含完整单词、适用的结构内部、含定界符的结构、更大轻量表达式、行内容／整行、段落及全文。不要求每处存在所有层级；相同边界不重复，无法识别结构时回退至可靠的通用文本层级。
- 区分行内内容、整行、空行和段落。整行是否包含末尾换行由实现定义并测试；真实换行与字面反斜杠加 `n` 不混淆。
- 多选区分别计算扩选，再按 CodeMirror 原生规则合并重叠范围及重复光标。保持主选区确定，不维护另一套独立光标身份。
- 每次有效扩选保留此前完整选区快照，包含全部范围、anchor／head 方向和主选区。`Ctrl+Shift+W` 按整次操作逐步恢复；扩选中发生合并后，仍恢复该步之前的多个范围，而非只缩小合并后的单个范围。
- 缩选到起点或没有有效历史时保持当前选区；不使用文本撤销模拟缩选，不恢复已过期的文档偏移。
- 文本变更（含撤销／重做）、主动重设选区（普通定位、导航、拖选、搜索定位等）、切换文档、重载或替换文档状态后清空历史。单纯滚动不视为重设选区；扩缩选自身不清空正在使用的历史。

例如 `foo(bar, baz);` 中光标位于 `bar` 内，适用层级为：

```text
bar → bar, baz → (bar, baz) → foo(bar, baz) → foo(bar, baz);
```

允许有意义的中间层；括号内部与含括号结构应分别可达，不跳过必要层级。继续扩选覆盖适用的段落或全文；连续缩选沿实际走过的步骤回到最初光标。

### 3. 轻量结构识别

- 支持 `()`、`[]`、`{}`、常见单／双引号及转义符；在低成本下兼容常见中文全角括号。
- 配对结构提供“内部内容”及“包含定界符”两层；嵌套时向外扩展。例如 `outer(inner(a, b), c)` 从 `a` 扩到内层括号内容、内层完整结构，再到外层结构。
- 引号内的括号、转义引号、混合引号、定界符边界和未闭合结构采用一致、保守的处理，不把明显不匹配或无关的文本拼成结构。匹配失败或超预算时，回退至可靠文本层级。
- 保留现有括号匹配高亮，先验证复用 `basicSetup`；引号只参与扩选，不新增配对高亮。
- 不引入全语言语法树，不要求精确识别各种原始字符串、模板插值或所有自然语言撇号用法。

### 4. 继承已有光标的列拖选

- `Ctrl+Shift+Alt+鼠标左键拖拽` 仅在编辑区触发。精确区分它与旧 `Alt+Shift` 手势，不能被旧连续范围逻辑抢先消费。
- 按屏幕文字布局及视觉列定位。纵向零宽拖拽在覆盖的每个视觉行建立独立光标；横向有跨度时建立逐视觉行的独立选区，不把首尾之间的全文变成一段连续选择。
- 每次拖拽结果为“拖拽开始前的选区集合 + 当前矩形覆盖产生的范围”，按 CodeMirror 规范归一化。折返时更新本次覆盖范围，不把沿途经过的所有光标永久累加；开始前的范围持续保留。再次列拖拽继续保留已有集合。
- 新增范围尽量成为主选区；合并及主选区归属沿用 CodeMirror 确定性规则。
- Tab、中文宽字符、软换行、字号及缩放均依据实际布局处理，不按 UTF-16 字符数冒充视觉列。同一逻辑行的多个软换行视觉行也在范围内；相同实际位置产生的重复光标允许归一化。
- 目标列超过某行内容时，该行光标／选区端点截到实际行尾，空行落在行首。不记录可编辑的行尾外虚拟位置，不自动插入空格或 Tab；后续输入从真实位置开始，用户明确输入的空格正常保留。
- 换行／空行可保留现有选区的必要可视化占位；占位宽度不表示真实空格，不参与文件数据。
- 区分点击和拖拽；未形成拖拽时不凭空创建跨行列选区。上下折返、自动滚动、跨出边缘、松开鼠标、修饰键释放和取消操作须稳定结束或更新，不残留拖拽状态。
- 保留 `Alt+Shift+单击` 增删光标、`Ctrl+Alt+↑/↓` 添加光标及普通连续拖选。旧 `Alt+Shift+拖拽` 在可低成本共存时保留追加连续范围；确有冲突时新手势优先，调整须在实现记录中说明。
- 检查原生 `Alt+拖拽` 的实际注册顺序及事件拦截，避免连带改变全部修饰键行为。列选区复用现有输入、删除、剪贴板及撤销机制。

普通左键从空行起步拖选时，起始空行也应被包含：

- 仅单击仍定位为空光标，不预先选中换行。向下拖选沿用正常范围；向上拖选时，若起始空行存在真实换行，将反向锚点扩到该换行之后，使复制文本也包含起始空行。折返至起点恢复空光标，改变拖选方向时重新计算，不积累换行。
- 末尾空行无真实换行可选时，锚点保持文件末尾，不补字符或越界；非空反向选择的该锚点保留空行视觉提示。其他选择的普通排除式终点不因此多画一行，单个空光标也不画蓝色背景。
- 此规则仅针对无修饰键、单击起步、逻辑行实际为空的普通拖选；非空行、双／三击及既有修饰键手势保持原有规则，不因纯选择修改正文、脏状态或文本撤销历史。

### 5. Island 风格选区视觉

- 选区采用 **3px 圆角**，保留蓝色、透明度、文本颜色及既有焦点／失焦表现。
- 普通连续跨行选区、智能扩选结果与列选区均按可见视觉行绘制真实已选内容；短行的右侧空白不填满编辑器，空行／被选中的换行保留可辨识的短占位。真实输入的尾部空格仍属于内容并正常高亮；部分首尾及软换行均按实际选中范围裁剪，再应用下述适度视觉留白。保持既有当前行背景，不把行尾裁剪误用于当前行提示。
- **末端留白**：选区末端增加适度留白，约半个编辑器基准字符宽作为起点，随字号／缩放保持协调；空行提示也相应加宽，避免只剩难辨认的细线。具体宽度可结合实机观感微调，不延伸为满行铺色。留白仅影响背景绘制，不增加真实选中文字、空格、光标位置或复制内容，并保持圆角、邻接接缝和多选区表现稳定。
- 相连的多行选区观感上为连续整体，邻行接缝不得出现透明孔隙、黑线、色差或断层。轮廓外凸角及内凹转折均以 3px 圆角处理，局部空间不足时限幅；不把每行强行画成独立四角圆角矩形，也不叠加半透明背景造成色差。
- 不相连的多选区保持独立；软换行、长短行交错及行首行尾处同样满足连续性。
- 搜索命中的黄色背景、当前命中边框、当前行背景及 012 动效的层级不退化。圆角仅影响绘制，不改变选中文本范围。
- 优先复用 `drawSelection`、公开几何及选区层，对行尾裁剪和圆角做针对性修正。原生跨行满宽矩形无法表达逐行贴合时，可用 CodeMirror 公开背景 layer 局部替代其背景，保持仅一套可见选区背景并保留原生光标／选择语义；不建立 Canvas／SVG 自绘体系或全局逐帧轮廓扫描。

### 6. 选择端点动画

- `Ctrl+W`／`Ctrl+Shift+W`、`Shift+方向键` 等键盘选择、已有选区时的键盘移动及鼠标拖选活动端点，复用 012 的光标移动过渡；鼠标拖选也明确纳入，不再一律立即对齐。
- 继续使用导航／普通单击的 150ms 过渡、190ms 清理及既有曲线；键入、组合输入、删除和粘贴保持 120ms／160ms。共用既有应用开关和系统减少动画偏好，不新增设置或独立动画系统。
- 文本、真实选择边界、输入位置及蓝色背景在事务中即时生效；仅可见光标端点平滑追随，不延迟鼠标命中或让整块选区背景缓动。连续移动从当前视觉位置接续，不排队。
- 沿用既有距离、可见性、多光标数量及文档规模降级；增减／合并光标、远距离跳转可即时对齐。IME、失焦、切档、重载、取消及搜索专有滚动保持原有正确性约束，不把任意程序定位都误判为交互动画。

## 约束与非目标

- CodeMirror 继续拥有实时正文与选择状态，不复制到 React 作为第二事实来源。新增用户操作遵守统一命令路径，菜单展示与实际快捷键一致，一次触发只执行一次。
- 扩缩选仅作用于编辑区，不抢占搜索框、Explorer、菜单或 Dialog 的编辑；IME 组合期间不干扰输入法。`Ctrl+F4` 复用既有关闭命令、可用性和未保存守卫，不绕开弹窗或关闭协调。
- 纯选区／高亮操作不得修改正文、文件格式、脏状态或文本撤销历史。列编辑实际变更遵循既有事务、撤销分组和保存规则；不改变 Rust 字节／BOM／EOL、IPC 或保存基线契约。
- 标签切换保留既有文档选区恢复能力，但清空本期扩选历史并终止拖拽；重载、外部变更恢复和销毁后不串档或遗留状态。
- 结构扫描、历史保留及可见轮廓计算应有明确上限或预算；大文档、长行、多选区和连续拖拽不触发无界扫描或无意义重绘。降级仍保持包含关系、真实文本定位及数据安全，具体参数在实现时记录并验证。
- 不引入 AST／Tree-sitter、索引、LSP、补全，不精确复刻所有语言的 IDEA 层级；不重做 012、全局主题、搜索 UI、Workspace 或文件监听。
