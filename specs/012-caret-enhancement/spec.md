## 目标

改善多光标编辑、IDEA 风格多选区复制粘贴、光标平滑移动与键盘导航引起的视口跟随。参考 JetBrains IDEA / Fleet 的体验，不要求完全复刻。

操作准确性与响应速度优先；动画只做可降级的视觉增强，不影响真实编辑位置、正文、选区和撤销历史。优先复用 CodeMirror 6，保持增量、小而完整的实现。

本文件是 012 的权威需求入口，汇总并替代本轮聊天中的需求草稿；既有阶段未被本期明确调整的行为继续有效。

## 本轮明确确认的决策

| 主题 | 决策 |
| --- | --- |
| 剪贴板 | 采用下文的原始分段分类及安全回退；实现后可结合体验小幅调整。文本原样处理，不解释字面 `\n`、`\t` 等转义序列。 |
| 普通方向键移动 | 边界处已不能移动的光标保留，其余光标继续移动；一次移动后位置相同即合并，允许三个变为两个。此规则不指“增加光标”命令。 |

| 动画开关 | 暂放现有下拉菜单，后续有设置功能时迁入设置。采用一个应用级开关控制光标与视口动画，保存偏好；系统减少动画偏好优先。 |

| 键入与组合动画 | 普通键入、拼音预编辑文本实际更新、候选文本实际更新及最终提交均参与光标平滑过渡；真实正文、选区与输入法即时更新。屏幕坐标不变时不制造动画；不能用字符索引相同判断屏幕位置不变。组合取消（Esc）、剪切及撤销重做立即对齐。 |

| 自动定位过渡 | 搜索等明确定位请求短距离平滑，大跨度先定位到目标附近再做短距离收尾；切换标签页、外部重载沿用原视口恢复行为。 |

## 行为与实现默认规则

本节补齐原始需求和讨论中的边界。未指定的布局、动画曲线、性能阈值及技术方案由实现者结合当前代码选择；偏离上述明确决策的行为需重新讨论。

### 1. 多光标创建、移动与选区

- `Alt+Shift+Click` 在点击处添加光标，再次点击已有光标可移除；最后一个光标不能被移除。允许同一行不同位置、不同逻辑行和不同长度选区，不引入虚拟空格。
- 普通点击／拖动恢复单选区；`Alt+Shift+Drag` 保留已有选区并新增一个普通连续选区；`Shift+方向键` 分别扩展各现有选区。重叠选区及重复光标交给 CM 原生规则归一化。
- 新增光标尽量成为主选区。删除、合并后的主选区采用 CM 的确定性策略，不维护另一套光标身份或完整添加历史。已有状态栏等主选区相关展示沿用既有语义。
- 提供向上／下增加光标的快捷键。从各现有光标向相邻逻辑行增加，保留原有光标，重复或越界时不新增；反方向增加不承担撤销上次添加的含义。
- 目标行较短时允许落在行尾，继续向长行增加时尽量恢复原目标水平位置。Tab、宽字符等位置计算复用编辑器几何与原生导航能力，不按字符串字符数自建列模型。
- 普通方向键移动先计算所有光标的实际目标位置，再合并重复位置。已到移动边界的光标保持在边界；其他光标移动到同一点时，在该次移动中合并，不额外等待下一次按键。同一行不同位置仍保留多个光标。
- 快捷键优先 JetBrains 习惯，同时检查现有命令、CM 默认绑定、系统和输入法冲突。上下增加可先评估 CM 的 `Ctrl+Alt+↑/↓`；不强制复刻 IDEA 的双击 Ctrl 手势，最终组合在交付时记录。
- 新手势仅在编辑区生效，不抢占搜索输入框、Explorer、菜单或 Dialog 的文本操作。检查 basicSetup 自带矩形选择及 Shift 扩选对 `Alt+Shift` 手势的影响，不以仅增加点击配置代替完整验证。

### 2. 同步编辑、历史与现有功能

- 所有光标同步输入字符、退格、删除、换行和既有缩进操作；每个非空选区分别被对应输入替换。优先使用 CM 原生多选区事务。
- 一次同步编辑作为一个事务，撤销／重做整体处理该次编辑及对应选区；连续普通输入沿用 CM 正常历史分组，不要求每个字符独立撤销。纯光标移动不新增文本撤销步骤。
- 检查已有自定义编辑命令是否只处理主选区，必要时最小修正。保持 CM 拥有实时正文，不将正文、光标或选区复制到 React 中另建事实来源。
- 多光标中文输入法需验证组合、候选选择、提交和取消；不漏输、不重复提交。组合期间优先使用正确的原生输入路径，Esc、导航和动画不得干扰候选操作。
- 查找预填仅读取主选区，并沿用现有预填限制及正则转义规则。搜索定位、上一个／下一个匹配、单次替换允许收敛到一个匹配选区；全部替换仍按原有搜索范围执行，不因存在多个选区重复替换。
- 搜索高亮继续只有一个“当前匹配”，不将所有与匹配重合的选区都当作当前匹配。保留 009／010 中查询、替换文本自己的既有解释规则；剪贴板“不解析转义”仅约束复制粘贴。
- 切换标签页保留各文档自己的多选区，取消视觉动画；重新加载等生命周期操作沿用原有状态与安全规则。

### 3. 多选区复制、剪切与粘贴

“一段”指一个原始非空选区的完整文本，可来自同一行，也可实际跨多行。字面反斜杠加 `n` 不等于换行；实际换行保留在段内，不用于拆解已知分段。

| 剪贴板情况 | 粘贴行为 |
| --- | --- |
| 能识别原始分段，段数等于多个目标选区数 | 按文档位置顺序一一对应，每段内部换行完整保留。 |
| 能识别只有一个原始分段，目标为多个选区 | 每个目标插入完整的同一段，即使段内行数恰好等于目标数。 |
| 多个原始分段，目标只有一个 | 各段以正常换行连接，作为普通多行文本插入。 |
| 多个原始分段，与多个目标数量不符 | 每个目标插入完整的换行拼接文本，不循环分配、截断或丢弃片段。 |
| 外部纯文本或原始分段信息不可用 | 沿用 CM 原生惯例：文本行数与目标数相等时逐行分配，否则每个目标插入完整文本。 |

- 源选区和目标选区均按文档位置排序，与添加顺序、主选区位置无关；目标非空时按上述规则分别替换。
- 原始分段保留保证至少覆盖同一应用窗口内、包括跨标签页的 Sorakada 复制粘贴。跨应用、跨窗口、应用重启或剪贴板历史流转后不保证分段仍在，缺失时使用纯文本回退。
- 优先调查、复用本地安装版本 CM 的剪贴板实现，仅在其按行分配无法满足原始分段需求处最小补充。保留对外可用的普通文本，不建设剪贴板管理器或历史系统。
- 分段信息必须与当前剪贴板内容对应；不可仅凭纯文本相同就复用旧分段。无可靠依据时视为普通文本，不误配过期片段。
- 空光标与非空选区混合时，只复制非空选区，不额外插入空段。所有选区为空时，保留 CM 原有整行复制／剪切及其粘贴惯例，同一行多个光标只处理该行一次；上述分段表针对普通选区复制。
- `Ctrl+X` 与复制使用相同分段规则，剪切删除和粘贴替换均为一次逻辑操作，能够整体撤销／重做。遵守既有只读限制。
- 尾部换行、空行、不同长度片段及 LF／CRLF 不得导致文本丢失、错配或破坏既有文件 EOL 语义。仅使用正常文本模型与既有边界转换，不新增剪贴板转义解释。

### 4. Esc 的分层退出

- 优先关闭当前最高层弹窗／菜单，再关闭搜索替换栏，最后将多选区收敛为主选区；一次按键仅消费一层。现有其他局部临时交互继续遵守 EscapeManager 的层级。
- 多选区收敛时保留主选区本身；若它包含选中文本，后续一次 Esc 可按原有 CM 行为折叠为光标。不能在同一次 Esc 内同时关闭搜索栏和清除多个选区。
- 统一处理 CM 默认 Esc 与应用 EscapeManager 的消费顺序，不能因为焦点在编辑器或搜索栏就出现相反优先级。IME 组合期间由输入法优先处理 Esc。

### 5. 光标平滑移动

- 常规键盘左右、上下和短距离导航提供短促、跟手的视觉过渡，可见多光标原则上均可参与。真实选区和编辑位置立即更新，选区高亮也立即更新，不等待动画。
- 光标导航与普通单击时长为 150ms；按后续实机反馈，文本编辑过渡单独缩短至 120ms。两者共用柔和曲线，连续操作跟随最新目标，中断旧动画，不排队或出现明显拖尾。
- 编辑内容区无修饰键的普通左键单击，从一个可见空光标到另一个单空光标的短距离定位，也提供轻量视觉过渡。与键盘光标动画共用时长、应用级开关及系统减少动画偏好；距离或可见性不适合动画时直接落位。
- 单击时真实光标位置按 CM 原生鼠标按下行为立即更新，不等待动画、鼠标松开或后续 `click` 事件，不为动画额外派发选区事务。连续单击可以中断旧过渡，紧接着输入仍作用于最新实际位置；单击仅增强光标视觉，不额外启动平滑视口滚动。
- 拖动建立选区时立即停止光标过渡，高亮及选区继续按原生行为更新。双／三击选词选行、带修饰键的扩选或多光标手势、非空选区定位、多光标收敛、点击行号栏或滚动条、右键、触摸及 IME 组合期间均不启用单击动画。
- 普通键入、拼音预编辑文本的每次实际更新、候选文本实际更新及最终提交，以及短距离退格、Delete、删除选区、粘贴，均提供 120ms 的轻量光标过渡，共用柔和曲线与动画开关。真实文本、选区及输入法行为即时生效，可见光标从当前视觉位置追随最新终点。
- 连续合法键入或拼音字母快速输入自然接续当前视觉状态，避免每个字符都先跳到上一目标或整串排队。候选切换或提交时若光标屏幕坐标没有变化，不制造动画。字符索引不变仍可能因字形宽度改变产生视觉位移，例如 `ni` 替换为“你好”；此类更新保留过渡资格，由 CM 测量及浏览器实际坐标变化决定是否产生动画。
- 优先保障原生输入法与候选框定位：CodeMirror 文本节点与原生选区即时定位，`.cm-cursor` 为独立图层，CSS 视觉过渡不拖慢或改变系统候选框位置；不拦截、不重放文本，不修改 composition DOM、提交、取消或撤销历史。
- 新的编辑意图在保持平滑接续的同时取消旧视口滚动和未决搜索请求。组合取消（Esc 或空提交）、剪切、撤销／重做及批量替换仍立即对齐；输入法组合状态与按键不借用键盘导航资格，不额外触发平滑视口跟随。删除、粘贴逐段检查实际变更大小，超过 500 个 UTF-16 单元或 5 个换行直接对齐；不因光标索引未变而误放行大段替换。向前 Delete 若屏幕坐标不变，不制造位移。
- 光标增减、合并、离开／进入可见范围或大跨度跳转时允许直接显示最终位置，不强行匹配新旧光标、不让光标长距离飞越屏幕。
- 只尽量处理可见光标；光标较多、大文件或高频导航时可降低乃至关闭动画，不影响全部真实光标的编辑。

### 6. 平滑视口跟随

- 覆盖 `Ctrl+Home`、`Ctrl+End`、`PageUp`、`PageDown` 及普通键盘导航造成的视口跟随，以主光标为跟随目标，不尝试同时容纳远距离分布的所有光标。
- 搜索定位、上／下一个匹配以及单次替换后定位下一匹配，也纳入视口过渡；搜索框持有焦点时同样生效。范围限于明确的定位请求，不将普通输入、鼠标定位或所有程序化滚动一概启用动画。切换标签页与外部重载仍沿用原有视口恢复，不播放自动定位过渡。
- 自动定位的短距离移动平滑到达；大跨度先直接定位到目标附近，再在有界距离内完成短收尾，不遍历中间内容。保持原定位请求的最终目标和对齐策略，尤其搜索居中习惯；目标已按请求对齐时无需多余晃动。无法可靠测量或存在复杂几何时允许正确定位优先的直接跳转回退。
- 以 120～180ms 为初始调试范围，滚动耗时不随距离线性增加。小、中距离短时过渡；数万／数十万行跳转可直接定位目标附近后短距离收尾，效果或性能不佳时允许直接跳转。
- 不逐帧滚动经过所有中间行。保持导航命令的最终位置和对齐习惯，尤其 `Ctrl+End` 应正常将文档末尾呈现在视口底部。
- 新导航替换旧目标；输入要求及时显示真实编辑位置。滚轮、触控板、滚动条拖动时取消旧动画，从当前视口交回原生滚动控制，不能事后拉回旧目标。
- 切换文档、失焦、重载、卸载以及尺寸／字体改变时清理旧动画并重新对齐；不留下旧文档的回调和视口目标。
- 光标与视口过渡协调，不能相互叠加造成远距离飞行或明显滞后。超长行的水平滚动本期允许保留原生行为；不全局启用 CSS smooth scrolling。

### 7. 动画偏好与性能约束

- 默认启用轻量动画；一个应用级开关同时控制光标与视口动画，暂放现有下拉菜单，后续迁入设置。保存偏好并遵循既有偏好管理方式，不建设完整 Settings。
- 尊重系统 `prefers-reduced-motion`，系统要求减少动画时关闭本期动画；设置或系统偏好变化时及时停止正在执行的动画。
- 优先复用 CM 的选区、历史、视口和测量能力；可评估 CSS、ViewPlugin、scrollHandler 等，不预先冻结实现方式。
- 避免动画每帧昂贵布局读取、全文计算或大规模视口渲染，控制新增依赖和复杂度。性能阈值由实现确定并记录，视觉降级始终优先于输入延迟。
- 本期全部动画的硬上限为文档不超过 200,000 行且长度不超过 10,000,000 个 UTF-16 代码单元，任一超限则光标和视口均直接定位。两项指标直接读取 CM 已有文档元数据，不扫描全文。硬上限内的十万行文档允许可见光标短距离动画，仍受数量、跨度、原生滚动等降级约束。
- 新菜单文案、快捷键说明和可访问名称遵守 011 国际化与统一命令路径。遵守 [AGENTS.md](../../AGENTS.md) 及[项目原则](../../.specify/memory/constitution.md)，保持保存基线、脏状态、Rust 字节／BOM／EOL 和 IPC 契约不变。

## 实现与验收记录

### 实际快捷键与交互实现
- **多光标点击/拖选**：`Alt+Shift+Click` 在点击处增删光标（保留最后一个光标）；`Alt+Shift+Drag` 增加独立连续选区。
- **垂直增减光标**：采用 CodeMirror 原生能力结合目标列保留，快捷键为 `Ctrl+Alt+Up` / `Ctrl+Alt+Down`。
- **分层 Esc 退出**：
  - 优先级分层：`MODAL (40)` -> `POPUP (30)` -> `TOOL (20)` -> `EDITOR (0)`。
  - POPUP 层中，打开的子菜单与顶层菜单均向 EscapeManager 登记；LIFO 机制保证子菜单先于主菜单关闭；关闭时交由 Base UI 内部机制流转，避免重复通告。
  - 编辑器基础收拢仅在获得编辑区键盘焦点时生效，不抢占 Explorer、搜索输入框或本地重命名。
- **动画偏好与菜单开关**：
  - 单一应用级持久化偏好 `editorMotion: boolean`（保存在 `UiPreferences`，默认 `true`，旧版本缺失时保守回退为 `true`）。
  - 下拉菜单在“视图”下提供“平滑光标与滚动”（`view.toggleEditorMotion`），启用时在图标槽位呈现勾选标记 `✓`。
  - 系统 `prefers-reduced-motion: reduce` 优先于应用开关，系统减少动画时实时停用所有动画。

### 动画参数与性能降级策略
- **光标平滑移动**：
  - 当前时长：导航与普通单击 150ms／清理 190ms；文本编辑 120ms／清理 160ms。共用 `cubic-bezier(0.22, 0.61, 0.36, 1)`，替代前段过快的曲线，固定触发延迟为 0。连续编辑与导航切换时更新视觉时长，不残留上一类操作的参数。文本编辑由统一 150ms 按后续手感反馈缩短，最终参数已获用户人工验收确认；这些是 Sorakada 的调试参数，不是已知的 Fleet 实现参数。
  - 普通单击动画已实现：复用键盘光标动画的时长和视觉机制，沿用短距离降级阈值，不增加独立开关；已随本期人工验收通过。
  - 单击候选的坐标及双向可见性在鼠标按下时读取并缓存，CM 更新期间只校验候选与实际事务，不读取布局、不延迟或补发选区事务。
  - 协调机制：当视口平滑滚动启动时，立即关闭当次光标 CSS 过渡，避免光标位移与视口滚动运动叠加导致跨屏飞越。
  - 降级与取消：
    - 光标数量 <= 10（大于 10 个光标降级为即时移动）；
    - 单次位移 <= 5 行且 <= 500 字符（大跨度直接落位，杜绝跨屏飞越）；
    - 光标数量发生变化（增删、合并）时直接落位；
    - 基础版本对所有正文变更立即对齐；2026-10-17 增量放行普通键入、拼音预编辑更新、候选更新与中文提交，以及短距离删除、粘贴的光标过渡；逐段检查实际编辑大小，等长大段替换也降级。等长短文本替换不因字符索引相同而取消，实际坐标不变时浏览器不产生多余过渡。组合取消、剪切、失焦及真实布局变化立即对齐／取消动画。正文变更不能被误判为全部需要关闭动画的布局变化；CM 更新期间禁止读取布局。
    - 全文硬上限为 200,000 行或 10,000,000 个 UTF-16 单元，任一超限均关闭光标和视口动画；硬上限内的十万行文档不再仅因行数禁用编辑光标过渡。
    - 鼠标按下先取消旧滚动与旧光标过渡，再依据第 5 节判定普通单击是否可启动新的光标过渡；开始拖选或出现排除条件时立即停止。鼠标定位不借用键盘导航资格。
- **视口跟随平滑滚动**：
  - 当前时长：180ms，曲线 `easeOutCubic` (`t => 1 - Math.pow(1 - t, 3)`)，以主光标为唯一跟随目标；由原 140ms 按实机反馈延长，已获用户人工验收确认。
  - 取消与防回拉生命周期：
    - 新导航按键按下（`keydown`）立即取消旧滚动 RAF，避免目标在当前视口内（`moveY < 1`）、坐标未就绪或大跨度走原生 fallback 时旧动画将视口强行拉回旧目标；
    - `handleScrollIntoView` 在任何分支（启动动画、无需滚动、原生 fallback）均首先清空旧动画；
    - 程序化选区变化（`update.selectionSet`）统一取消旧滚动动画，防止搜索或无 userEvent 的程序定位被正在运行的 RAF 回拉；
    - 用户滚轮（`wheel`）、触控板（`touchmove`）、点击或拖动滚动条（`pointerdown`）、编辑意图与输入法组合（`beforeinput`/`compositionstart`）、输入（`docChanged`）、失焦（`blur`）、非键盘定位事务（`select.search` 等）或切换 Tab（`destroy`）时立即取消动画，当前视口交回原生控制，绝不回拉旧目标；
    - `destroy` 对称清理所有 DOM/窗口事件监听、timer 与 RAF。
  - 复杂几何与原生回退：
    - 普通键盘导航的视口动画仍限于 <= 50,000 行；硬上限内的搜索定位允许大文件短收尾。该门槛与可见光标动画硬上限分开，超过 200,000 行或 10,000,000 个 UTF-16 单元则全部直接定位；
    - 视口距离差 <= 2500px（超大跨度直接跳转，不逐帧遍历中间内容）；
    - 坐标尚未计算或虚拟化未就绪时回退至原生即时滚动；
    - 存在非零竖向面板边距（`scrollMargins.top/bottom > 0`，保留行号等固定左右 gutter 动画）、DOM 变换缩放（`scale != 1`，排除正常 12px 滚动条槽）、非 LTR 文本方向或需要水平滚动调整（`moveX >= 1`，含 gutter 遮挡）时，直接回退至 CodeMirror 原生滚动，确保复杂几何完全由 CM 权威管理。
