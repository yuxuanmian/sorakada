# Sorakada 015 — Windows 文件关联与外部文件打开

**日期**：2026-10-28

**版本定位**：小型功能扩展

**状态**：已实现，人工验收基本通过（2026-10-28 用户确认）；本文为 015 的权威规格。

## 目标

Windows 安装版能够声明支持常见文本、代码及配置文件；Sorakada 能接收操作系统或命令行传入的文件路径，在冷启动或已运行状态下，统一交给主窗口的现有文件打开与标签管理流程处理。

优先复用 Tauri 2 官方能力，以不改变用户默认应用为优先约束。仅在安装器关联注册与清理环节允许必要且范围有限的适配；应用运行时不管理注册表。除必要适配外，不改变现有编辑功能和 UI 行为。

## 决策与范围

### 1. Windows 文件关联与安装器

- 仅支持 Windows 10/11 x64 的 NSIS 安装版，正式放弃便携版支持。沿用 [011 规格](../011-app-foundation/spec.md) 的当前用户安装、简体中文安装器及其他无关打包选项；正式安装版标识 `com.sorakada.editor` 保持稳定。
- 以 Tauri `bundle.fileAssociations` 作为扩展名声明的唯一来源，安装器适配复用该声明，不另行手写一份扩展名列表。关联列表不要求与 [014 语言支持](../014-basic-syntax-highlighting/spec.md) 严格一致，也不是文件打开白名单。
- 首版登记以下扩展名，不提供安装期间的逐项勾选，也不设计文件类型专属图标。

| 分类 | 扩展名 |
| --- | --- |
| 普通文本 | `txt`、`text`、`log` |
| Markdown | `md`、`markdown` |
| 配置与数据 | `json`、`jsonc`、`xml`、`yaml`、`yml`、`ini`、`cfg`、`conf`、`properties`、`toml`、`csv` |
| 常见代码 | `c`、`h`、`cpp`、`hpp`、`java`、`kt`、`rs`、`go`、`py`、`js`、`jsx`、`ts`、`tsx`、`html`、`css`、`scss`、`sql` |
| 脚本 | `sh`、`bat`、`cmd`、`ps1` |

- 安装器仅将 Sorakada 登记为可选打开程序，默认应用由用户通过 Windows 选择。不得修改扩展名默认关联值或 Windows 的用户选择；没有用户显式选择时，也不得通过安装将 Sorakada 自动设为默认应用。
- 使用带 Sorakada 命名空间的文件类型标识及必要的候选程序注册项，避免覆盖其他程序的类型定义。安装、重复安装与升级均遵守上述约束。
- 卸载只清理 Sorakada 自己的候选项和类型定义，不删除整个扩展名注册项，不覆盖其他程序后来写入的内容，也不恢复所谓“安装前默认应用”。
- 适配应直接避免原生关联宏的默认值写入和旧默认值恢复，不能先改变默认关联再事后恢复。不得发展为通用注册表管理、关联修复工具或应用运行时注册逻辑。
- 系统打开命令须分别正确引用可执行文件路径和文件参数，例如 `"C:\某个目录\Sorakada.exe" "%1"`；安装目录及文件路径包含空格、中文时仍须有效。

**相对初稿的确认修订**：初稿“仅使用原生 `fileAssociations`，不额外维护注册表脚本”的绝对限制，由本节的有限安装器适配取代。讨论时项目锁定 Tauri CLI 2.11.4，其原生 NSIS 关联宏会写扩展名默认值，卸载宏会恢复备份值，无法直接满足本版优先约束。具体适配方式由实现者确定，不复制或改造无关安装逻辑。

### 2. 外部入口、单实例与主窗口

- 支持设为默认应用后的资源管理器双击、Windows“打开方式”、命令行单文件及多文件参数。操作系统可能为多选文件连续发起多个启动请求，所有收到的请求均经过同一入口处理。
- 引入 Tauri 官方 Single Instance 插件，并按官方要求优先注册。冷启动单独读取首次启动参数与工作目录；不能仅处理插件的后续实例回调。
- 保持一个 Sorakada 主应用实例，允许短暂的第二次启动进程及 WebView2 子进程，不限制未来同一应用内的多个窗口。本版不实现多窗口。
- 外部请求始终投递至明确标识的主窗口，当前标签为 `main`，不根据当前聚焦窗口选目标。只建立必要的主窗口定位能力，不新增窗口管理系统。
- 收到外部启动请求后，尝试显示、恢复最小化并激活主窗口，再处理文件；保持原有正常／最大化状态。激活失败不能阻止文件打开，Windows 是否最终授予前台焦点不作绝对保证。
- 无文件参数时正常启动或激活主窗口，不创建空标签。请求全部失败或只有被忽略的目录时，仍执行窗口激活尝试。
- 开发版与正式安装版隔离单实例身份，避免开发验证被已安装应用接走；正式版身份保持稳定。不增加用户可配置的实例或窗口选项。

### 3. 参数与现有文件打开语义

- 直接接收操作系统／运行时已拆分的参数数组，排除可执行文件参数；不得重新按空格拆分、手动剥除路径引号或通过拼接 Shell 命令执行文件打开。
- 支持绝对路径、基于该次请求来源工作目录的普通相对路径，以及中文、空格、Unicode 和 UNC 路径。不得借用现有应用的工作目录解析后续实例的相对路径，也不得修改进程工作目录来处理请求。
- 命令行以文件路径参数为主，可使用 `--` 结束选项解释；不新增行列定位等 CLI 功能。不额外展开通配符、环境变量、`~`，不解释 URL。异常或不支持的输入不得使应用退出，沿用现有错误提示方式。
- 外部请求通过统一分发入口，最终复用 `DocumentManager.openPath` 及现有身份解析、读取、错误处理和标签管理，不建立第二套加载机制或路径所有权索引。
- 请求内按参数顺序处理，多个请求按应用接收顺序处理，避免批次交错打乱顺序。单个文件失败继续后续文件，不创建空白或半初始化标签。
- 最后一个成功打开或激活的文件成为活动标签；整批没有成功处理的文件时保留原活动标签。失败通过现有通知机制呈现，不增加批量错误 UI。
- 重复路径沿用现有规范路径身份与并发打开去重，激活已有标签。重复请求本身不强制重读磁盘，保留已有未保存内容、撤销历史、选区和滚动状态；现有外部变更检测规则继续适用。不额外承诺将不同硬链接路径合并。
- 不存在的文件报打开失败，不自动创建新文档；目录沿用批量拖放规则忽略，不打开工作区。外部文件不自动切换工作区，也不自动打开其父目录。
- 未登记关联或未知扩展名仍可传入，由现有读取能力判断是否可打开。二进制、不可访问、现有编码或行尾规则不支持的文件沿用现有失败语义；登记 `.txt`、`.ps1` 等不代表新增 GBK、UTF-16 等编码支持。脚本只作为文本打开。

### 4. 初始化、模态操作与退出

- 冷启动与后续实例请求共用最小必要的待处理协调机制。主窗口未准备好时暂存，准备好后处理；正常运行期间按序分发。事件可以通知有待处理请求，不能成为请求唯一存储。
- “就绪”指 DocumentManager、请求接收器及必要订阅已初始化，不要求已有 CodeMirror 视图。现有空白首页不挂载编辑器，首个文件须能够先打开并驱动视图创建，避免相互等待。
- 正常启动和运行的应用生命周期内，请求交接不得因监听建立时序、就绪切换、React StrictMode 订阅重装而丢失或重复消费。窗口尚未创建时也不能因定位失败丢弃待处理请求。
- 应用确认弹窗、原生打开／另存为选择框及其所属操作未结束时，外部请求暂存；操作完成或取消后继续处理。必要时在文件之间重新检查阻塞状态，不照搬拖放在交互受阻时直接忽略请求的行为，也不为此更改内部拖放语义。
- 原生选择框当前直接调用插件，未进入 `dialogManager` 的模态状态，实施时须补齐最小必要的状态协调；不能只检查 `dialogManager.isActive()`。
- 退出确认期间暂存请求；取消退出或退出失败且应用继续运行后处理。用户最终确认退出后，退出优先，终止接收和处理，不承诺退出竞态下自动重投、重启或跨进程恢复请求。
- 待处理状态不持久化，不为崩溃恢复提供交付保证。不引入复杂消息队列、轮询系统或多窗口通信框架。

## 架构与实施约束

- [仓库规则](../../AGENTS.md) 与 [项目宪法](../../.specify/memory/constitution.md) 继续适用。CodeMirror 独占实时文本；Rust 的字节／BOM／EOL 处理仍归 `file_codec.rs`；保存基线、脏状态、撤销／重做及成功另存为才更新路径的规则不变。
- 本规格将 011 未包含的文件关联与默认打开方式纳入 015，不改变 011 的其他安装和 UI 决策；早期版本对系统外部打开的范围排除不再约束本功能。
- 当前接入基线：`src-tauri/tauri.conf.json` 为安装与 `main` 窗口配置；`src-tauri/src/lib.rs` 为插件、状态与命令接入点；`src/app/App.tsx` 连接文档管理和原生窗口生命周期；`DocumentManager.openPath` 已具备规范路径去重与并发打开去重；现有 `processDroppedPaths` 的批量规则可复用，但阻塞时丢弃请求的策略不能用于外部打开。
- 修改集中在关联配置、有限安装器适配、外部请求接收／分发及必要生命周期接入，避免无关重构。新增 IPC 边界须有明确契约及两侧一致性验证。
- Leader 负责关键技术决策、合理委派、审查、集成与必要验收；Worker 只做有关实现及定向检查。实现前后核对本节的职责、数据安全、统一入口与复杂度约束，不另建完整测试体系。

## 非目标

便携版及其关联兼容性、应用内关联设置页、自动更改 Windows 默认应用、通用注册表管理或关联修复工具、安装扩展名选择界面、自定义文件类型图标或编辑行为、多窗口创建／拆分／跨窗口移动、编码检测转换优化、搜索替换增强、文件预览及资源管理器右键菜单扩展均不属于 015。

未来设置系统可提供跳转 Windows 默认应用设置的入口，本版不实现。本文不要求创建独立 `plan.md` 或 `tasks.md`，也不授权直接开始实现。

### 用户：真实安装包

- NSIS 安装后能在 Windows“打开方式”中选择 Sorakada，安装前后的默认应用不被主动改变。
- 用户主动设置为默认应用后，双击及多选打开文件可用；应用已运行、最小化等情况下从资源管理器打开行为正确。
- 实际安装目录含空格或中文时，Shell 打开命令有效。
- 重复安装、升级不抢占默认应用；安装后用户改选其他默认应用，卸载 Sorakada 不覆盖该选择，且自身候选项正确清理。
- 不同 Windows 版本及真实 Shell 行为符合预期。

**未决设计阻塞项**：无。具体适配方式、请求交接协议与最小状态结构由实现者在上述边界内确定；发现新的实质冲突时先分析影响，再反馈调整。

## 实现与验证记录

- **2026-10-28 实现完成，尚未人工验收**：已配置 37 个扩展名；有限 NSIS hook 替换默认关联注册／清理宏，仅登记自身 ProgID 和 OpenWith 候选项。卸载在打开命令仍归本安装目录时才删除类型定义；正式标识、当前用户安装和简体中文配置保持不变。应用运行时没有新增注册表管理。
- 官方单实例插件优先注册，冷启动先入共享 FIFO，后续实例使用各自参数和工作目录入队。主窗口通过非破坏性 peek／队首 ack 消费，事件只负责唤醒。开发构建在运行时使用 `.dev` 标识，正式标识不变。
- App 持有稳定串行消费者，保留暂停和 StrictMode 重装期间的批次进度；确认已生效但回包失败时核对原生队首，不重开旧文件。原生选择框及所属操作通过轻量嵌套活动计数暂缓外部打开，已提交退出后不恢复消费；活动计数不扩大内部命令、标签和拖放的交互限制。

- **打包入口补充**：新增 `npm run package`，正式构建成功后将当前配置版本的 NSIS 安装包导出到仓库根目录 `release/`；README、CI 上传目录与实机清单链接同步更新。导出脚本语法检查和实际复制通过，导出包与原包 SHA-256 一致；此工具调整未重跑全量测试。
