## CP01：安装，默认程序不变

1. 运行本次安装包。如果已有旧版，可先覆盖现有安装并记录该场景；不要将覆盖安装记录成全新安装。
2. 若向导允许选择目录，建议使用当前用户目录下的 `Sorakada 验证`，同时覆盖安装路径包含中文／空格的场景。已有安装保留原路径时，将此路径场景单独记为未测。
3. 完成后，先不将 Sorakada 设为默认应用，分别双击 `.txt`、`.md`、`.json` 测试文件。

- [ ] 安装器保持简体中文、当前用户安装，无扩展名勾选页。
- [ ] 原有默认程序与 CP00 一致，没有因为安装被切换成 Sorakada。
- [ ] 安装后的 Sorakada 能正常启动。

下面 PowerShell 示例仅用于向安装版传入路径。先将 `$exe` 改为**实际安装后的**可执行文件，不使用源码构建目录的 exe，不依赖旧快捷方式：

```powershell
$exe = Join-Path $env:LOCALAPPDATA 'Sorakada 验证\sorakada.exe'
$caseDir = 'D:\project\tool\sorakada\logs\015-manual-fixtures'
Get-Item -LiteralPath $exe
```

- [ ] “打开方式”的可选程序中有 Sorakada；若必须手动浏览 exe 才能找到，记录为候选程序登记异常，不直接勾选通过。
- [ ] 三种文件均作为文本打开，文件名和正文正确。
- [ ] 仅本次打开不改变原有默认程序；用户明确设为默认后，双击 `.txt` 才进入 Sorakada。
- [ ] 包含中文／空格的安装路径可正常接受系统打开请求（若 CP01 使用了这种路径）。

## CP07：工作目录、特殊路径与未知扩展名

在 Sorakada 已运行时逐段执行；每个 `Push-Location` 均配有 `Pop-Location`：

```powershell

Push-Location -LiteralPath (Join-Path $caseDir 'sub')

```

- [ ] 根目录 A 和子目录 A 是两个不同文件；分别选中时，路径和 `ROOT A`／`SUBDIRECTORY A` 正文正确。
- [ ] 后续实例的相对路径没有被按第一个实例的工作目录解释。

## CP09：原生打开／另存为期间暂存请求

本项每个分支选一个当前尚未打开的文件作为外部目标；可先关闭对应测试标签。

1. 在 Sorakada 按 Ctrl+O，保持 Windows 文件选择框打开。
2. 切换到资源管理器，外部打开一个测试文件，再回到选择框，选择“取消”。
3. 再次 Ctrl+O，外部打开另一个测试文件，然后在选择框中正常选择文件并打开。
4. 创建未命名文档，输入测试文字，按 Ctrl+S；保持另存为选择框打开，再发一个外部请求。先测取消另存为；重新操作一次并保存到 `$caseDir` 下的 `saved-checkpoint.txt`。

- [ ] 原生选择框期间，外部请求没有直接改变正在操作的标签，也没有丢失。
- [ ] 取消或完成原操作后，待处理文件才依次打开。
- [ ] 另存为成功时，`saved-checkpoint.txt` 包含未命名文档的测试文字，没有把外部文件内容保存进去；取消时未命名文档和未保存状态保留。
